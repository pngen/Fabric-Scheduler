# Fabric Scheduler multiprocess proof specification

Repository: E:\The Journey\Coding\GitHub\production\Fabric-Scheduler (C++20, MSVC /W4 /WX).

## Goal
Build a REAL distributed reference deployment using independent OS processes over framed loopback TCP, and prove: registration, candidate publication, deterministic scheduling (A wins), commit, execution handoff, worker death -> fencing -> old plan revalidation -> B wins, stale replay rejection, coordinator restart/recovery.

## Deliverables
1. tools/coordinator_main.cpp : reads args "--port <p>" "--state-file <path>"; runs WinsockInit; owns a Scheduler (Config: policy generation 1, maxCandidatesPerRequest 64); a thread-safe in-memory ResourceBroker (mutex; commit returns success with a token and records resource generation; supports a "failNext" test hook via a control message), and a ReferenceExecutionAdapter(AuthorityGeneration(1)) OR a broker/exec that accepts the scheduler's current authority (coordinator must accept the authority it issues; simplest: use ReferenceExecutionAdapter(AuthorityGeneration(1)) since the scheduler starts authority=1, but if a plan is generated with a DIFFERENT authority, accept it — implement a custom ExecutionFabric that authorizes when the plan authority equals the scheduler.current_authority()). IMPORTANT: handoff must succeed when the plan is current, so implement an ExecutionFabric that returns {authorized=true} if plan.authorityGeneration >= accepted threshold you choose and the plan is not stale. A simple robust choice: a custom ExecutionFabric::authorize(plan) returns authorized when plan.authorityGeneration value equals scheduler.current_authority() value; pass the scheduler to it.
   - Accept loop: while running, TcpListener.accept() (blocking). Accept a connection, spawn a std::thread that serves it. The thread keeps a workerId/boot once REGISTER is received. Serve frames until the socket closes (recv_frame throws/returns), then on unexpected disconnect: call scheduler.fence_worker(boot) and scheduler.set_epoch(epoch+1) to fence everything (conservative). 
   - Message handling (dispatch on MessageType):
     * HELLO: reply a HELLO with the coordinator epoch.
     * REGISTER: decode payload (workerId u64, bootId u64, name string) via ByteReader; record worker; reply an ack frame (REGISTER with a status byte or just echo). Use MessageType::REGISTER as ack with payload = u8 status.
     * PUBLISH_RESOURCE / PUBLISH_CAPACITY / PUBLISH_CONGESTION / PUBLISH_HEALTH: decode a full Candidate via decode_candidate_record(ByteReader) and call scheduler.ingest_candidate(candidate). On success send a PLACEMENT_PLAN? No - send an empty ack (e.g. PUBLISH_RESOURCE with u8 status=1) ; on FabricError send an ERROR frame (code u16 + message). These four message types all carry a full Candidate (simplest, honest: each publish message carries the whole candidate snapshot; document it).
     * SUBMIT_WORKLOAD: decode SchedulingRequest via decode_request_record; run scheduler.schedule(req,&dep,&policy) with AlwaysReadyDependency and AllowAllPolicy; encode the resulting PlacementPlan via encode_plan_record + also the decision's summary; send PLACEMENT_PLAN frame with (u8 producedPlan, plan bytes via encode_plan_record). If no plan, send PLACEMENT_PLAN with producedPlan=0 and an error reason string.
     * COMMIT_REQUEST: decode planId u64; broker is the coordinator's broker; call scheduler.commit(planId, broker); encode ResourceCommitResult {u8 succeeded, resourceGeneration u64, string token, string failureReason}; send COMMIT_RESULT.
     * EXECUTION_HANDOFF: decode planId u64; call scheduler.handoff(planId, exec); encode ExecutionHandoff {u8 authorized, authorityGeneration u64}; send EXECUTION_RESULT.
     * REVALIDATE: decode planId u64 + 12 u64 generations; call scheduler.revalidate(planId, fp); encode {u8 current, u32 changeCount, changes as strings}; send back as REVALIDATE.
     * CANCEL: decode requestId u64; scheduler.cancel(reqId); ack.
     * SUPERSEDE: decode old u64, new u64; scheduler.supersede(old,new); ack.
     * SAVE: serialize scheduler.snapshot() via persist_save to the --state-file; ack SAVE.
     * SHUTDOWN: reply SHUTDOWN; set running=false; close.
2. tools/worker_main.cpp : args "--port <p>" "--name <w>" "--boot <b>" "--mode <mode>" "--wait-ms <ms>" "--scenario <A|B|A2>". Connects to 127.0.0.1:port via TcpChannel::connect; sends REGISTER (workerId, bootId, name); then publishes a Candidate via the appropriate PUBLISH_* (use PUBLISH_RESOURCE carrying a full candidate) built from a deterministic factory (see scenario): mode "A" = local (numaDistance 0, pcieHops 1, vramAvailable 16GiB, congestion 0, stateLocal true, provenance REPORTED); mode "B" = remote (numaDistance 2, pcieHops 3, vramAvailable 8GiB, stateLocal false); mode "A2" = the A candidate but with congestion 0.95 and congestionGeneration 2. Worker keeps the connection open (loop recv_frame; ignore frames; on ERROR print) so the coordinator sees it alive. On SHUTDOWN/close, exit. Use WorkerBootId from --boot. Use SourceBootId = a fresh value (e.g. %100000 + boot). After publishing, print "PUBLISHED <name>" to stdout, then idle.

- NOTES:
  - WinsockInit must be constructed once per process before using sockets.
  - On Windows, CreateProcess needs a command line; use CreateProcessW with the full path of the exe (query via GetModuleFileNameW or pass the exe path as an arg to the test). Build the exe paths from the test's own module directory.
  - Closing sockets cleanly; kill child processes on failure and at end. Do not leave processes running.
  - The coordinator must be thread-safe: its Scheduler is internally locked; the broker and exec must be mutex-protected if shared across threads.
  - The coordinator's set_epoch on worker disconnect must be monotonic; do not call set_epoch twice with the same value (it throws if it regresses; equal is a no-op).
